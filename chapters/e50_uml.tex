\section{Diagrama de clases --- agente PEP}

La figura~\ref{fig:diagrama-clases-agente} presenta las clases del agente. La configuración (\texttt{AgentConfig}) reúne las carpetas vigiladas, los marcadores de procesos y aplicaciones, los parámetros del sondeo y del \emph{buffer} local y la dirección de la API. Cuatro colectores (archivos, procesos, aplicaciones sensibles y red) generan señales comparando dos consultas sucesivas del sistema operativo; el \texttt{Debouncer} descarta las repetidas y limita su frecuencia, y \texttt{EventFactory} las convierte en eventos con el formato del contrato de la API. \texttt{ScoringClient} envía cada evento, conserva los no enviados en el \emph{buffer} local y abre el \emph{circuit breaker} ante rechazos de autenticación, mientras que \texttt{Enforcer} aplica la acción indicada por la API y conserva el respaldo necesario para revertirla. La versión completa, con todos los atributos y operaciones, se presenta en el Anexo~H.

\section{Diagramas de clases --- API PDP}

La figura~\ref{fig:diagrama-clases-api} presenta la vista de paquetes: el estado de cada usuario en Redis (A), el cálculo del puntaje híbrido (B), los servicios de IAM, autenticación, deduplicación y notificaciones (C), las rutas HTTP con la configuración, el historial y el reentrenamiento (D) y los contratos de datos (E), con las dependencias entre ellos.

La figura~\ref{fig:diagrama-clases-api-redis} detalla el estado que la API mantiene por usuario en Redis (\texttt{User\-Scoring\-State}), compuesto por la continuidad de la secuencia de eventos, el acumulado diario de Isolation Forest, el \emph{buffer} del LSTM, el ancla del puntaje híbrido y la línea base personal, cuyas estadísticas se actualizan en forma incremental con el algoritmo de Welford.
